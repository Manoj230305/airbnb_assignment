PROMPT 01: PROJECT ARCHITECTURE, SCAFFOLDING & DUAL-PROCESS WORKFLOW
================================================================================
"You are a Senior Full-Stack Engineer scaffolding a pixel-perfect Airbnb listing detail page clone for a technical evaluation.

Objective:
Set up a clean, zero-configuration full-stack repository combining a modern React frontend with a lightweight Node.js Express backend.

Technical Stack & Constraints:
1. Frontend: React 19 + Vite.
2. Icons: lucide-react (pure SVG icons).
3. Backend: Express 5 + cors (ES Module format, `"type": "module"` in package.json).
4. No external CSS frameworks (no Tailwind, Bootstrap, or component UI libraries). All styling must use modular Vanilla CSS.
5. Dev Orchestration: Use `concurrently` so that running `npm run dev` starts both the Express server (port 5000) and the Vite development server (port 5173).
6. Reverse Proxy: Configure `vite.config.js` to proxy all `/api` requests to `http://localhost:5000` with `changeOrigin: true` to prevent CORS issues in development.

File Requirements:
- `package.json`: Include scripts for `dev` (concurrently), `dev:client`, `server`, `build`, and `lint`.
- `vite.config.js`: Include React plugin and `/api` proxy target.
- `.gitignore`: Standard Node/Vite ignore rules (node_modules, dist, .env, *.log).

Acceptance Criteria:
- Running `npm run dev` boots both servers simultaneously without terminal collisions.
- Frontend fetches to `/api/...` resolve cleanly to the Express instance."

PROMPT 03: NODE.JS EXPRESS REST API & ATOMIC JSON PERSISTENCE STORE
================================================================================
"You are a Backend Systems Engineer building a zero-dependency REST API for an Airbnb single-page clone.

Objective:
Create an Express 5 backend with file-backed persistence so reviewers can run the application instantly without configuring MongoDB, Docker, or PostgreSQL.

Implementation Plan:
1. `server/data/initialData.js`:
   - Export default listing data and initial blocked date seed (e.g. November 18-24, 2026).
2. `server/data/store.js`:
   - Implement a `Store` class managing atomic reads and writes to `server/data/db.json`.
   - On boot, if `db.json` is missing or corrupt, initialize from `initialData.js`.
   - Method `getListing()`: Return listing metadata with dynamic review count and ratings.
   - Method `getAvailability()`: Return active blocked date ranges.
   - Method `createReservation({ checkInDate, checkOutDate, guests, guestName, promoApplied })`:
     * Validate date format and ensure `checkInDate < checkOutDate`.
     * Date collision check: If the range overlaps with any existing booking, throw an error with status 400.
     * Price calculator: Calculate baseSubtotal (nightlyRate * nights), 10% promo discount (if applied), cleaning fee (₹1,200), service fee (8%), and GST taxes (12%).
     * Generate unique booking code (`BK-XXXXXX`).
     * Append to reservations, persist to disk, and return confirmed booking payload.
   - Method `getReviews(query, sort)`: Filter reviews by search term and sort by highest/lowest rating.
   - Method `addReview({ author, rating, text })`: Add review, recalculate average listing rating, persist to disk.
3. `server/index.js`:
   - Express server listening on PORT 5000 with CORS and express.json().
   - `GET /`: Serve a clean, modern HTML API Explorer dashboard with clickable links to all endpoints.
   - `GET /api/health`: Health status, uptime, timestamp.
   - `GET /api/listing`: Full listing JSON with embedded blockedRanges.
   - `GET /api/availability`: Blocked calendar date ranges.
   - `POST /api/reserve`: Reservation creation endpoint returning 201 Created or 400 Bad Request.
   - `GET /api/reviews`: Filterable/sortable reviews endpoint.
   - `POST /api/reviews`: Review creation endpoint.
   - `POST /api/inquiries`: Contact host inquiry endpoint.

Acceptance Criteria:
- Passing overlapping dates to `POST /api/reserve` returns HTTP 400 with a descriptive collision message.
- Valid reservations return an itemized pricing breakdown and persist across server restarts."
